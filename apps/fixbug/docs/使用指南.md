# Infini 运维 Agent — 使用指南

面向**本机 + SSH 远程服务器**的只读运维 Agent：监控对话、规则分析报告、按主机授权、Cron 自动化。  
Web 界面默认入口：`http://localhost:3000/monitor`。

---

## 1. 安装与运行

### 环境要求

- Node.js 22+（与 Next.js 16 / AI SDK 7 一致）
- **pnpm**（仓库指定 `packageManager`）
- 系统已安装 **OpenSSH 客户端**（`ssh` 在 PATH 中，用于远程主机）
- Linux/macOS 本机 Agent 体验最佳（采集 `/var/log`、`journalctl` 等）

### 启动

```bash
cd infini-fixbug
pnpm install
pnpm dev    # 开发：http://localhost:3000
# 或
pnpm build && pnpm start   # 生产
```

进程需**常驻**（`dev` 或 `start`），Cron 定时任务才会在进程内触发。停止服务即停止调度。

## 2. 界面导航

| 页面 | 路径 | 作用 |
|------|------|------|
| **监控** | `/monitor` | 对话式只读巡检（本机或指定 SSH 主机） |
| **分析** | `/analysis` | 规则引擎报告列表与详情；支持删除、按批次筛选 |
| **主机** | `/hosts` | 登记 SSH（OpenSSH 配置格式） |
| **权限** | `/agent` | **每台服务器**单独授权与全局命令/路径白名单 |
| **自动化** | `/automation` | Cron 定时任务与执行记录 |
| **Skills** | `/skills` | Agent Skill 列表与自定义（`SKILL.md`） |

### Agent Skills

与 [Cursor Agent Skills](https://cursor.com/docs) 相同思路：每个 Skill 是一个目录 + `SKILL.md`（YAML frontmatter + Markdown 正文）。

Skill 仅存放在 **`.agent/skills/<name>/SKILL.md`**（见 `.agent/README.md`）。内置 Skill 在 frontmatter 设 `readonly: true`；Web 新建的非只读 Skill 可删除。

**匹配规则：** frontmatter 里 `triggers` 关键词 + `description` 与用户问题 / 分析报告文本匹配；监控 LLM 对话会把命中的 Skill 正文注入 system prompt；规则分析报告会在「下一步决策」中引用相关 Skill。

**格式示例：**

```markdown
---
name: my-check
description: 一句话说明何时用
triggers:
  - 关键词1
  - 关键词2
---

# 排查步骤（Markdown）
...
```

推荐首次使用顺序：**主机 → 权限 → 分析（试跑）→ 自动化（默认可用）→ 监控**。

## 3. 主机（SSH）

### 3.1 添加远程服务器

1. 打开 **主机** 页。
2. 在编辑器中粘贴 OpenSSH 片段（与 `~/.ssh/config` 相同），例如：

```ssh-config
Host my-prod-01
    HostName 203.0.113.10
    User deploy
    Port 22
    IdentityFile ~/.ssh/id_ed25519
```

3. 点击 **保存配置文件并加载主机**（写入 `data/ssh-hosts.conf`）。

仓库模板：`config/ssh-hosts.example.conf`。

### 3.2 其它加载方式

- 环境变量 `SERVER_SSH_CONFIG=/path/to/config` 可读指定文件（见 `src/lib/ssh/store.ts`）。
- 未设置时还会尝试 `data/ssh-hosts.conf`，以及本机 `~/.ssh/config`（只读合并，编辑仍写入 `data/ssh-hosts.conf`）。

### 3.3 连接测试

主机卡片 **测试连接**。前提：该主机已在 **权限** 页 **单独授权**（见下节）。

### 3.4 远程执行约束

- 使用系统 `ssh`，**BatchMode**，无私钥交互。
- 远程命令必须在 **权限 → 全局命令前缀** 白名单内（如 `df -h`、`journalctl`、`tail`、`cat`）。
- **不支持** shell 管道、`;`、`&&`、`` ` `` 等元字符。
- 与本地共用白名单；远程不要求单独开启「运行白名单命令」即可做**只读监控类**命令（分析、SSH 监控工具），但 **写操作 / 自动化命令** 仍受各主机 grant 控制。

## 4. 权限（按服务器授权）

策略文件：`data/server-agent-policy.json`（结构：`shared` + `local` + `hosts`）。

### 4.1 切换服务器

1. 在 **权限** 页使用 **「选择要配置的服务器」** 下拉框（或下方标签）。
2. 若只有 **本机**：请先在 **主机** 页登记 SSH，保存后刷新权限页即可出现远程主机。

### 4.2 每台服务器

- **授权 Agent 访问**：总开关。关闭后该台不参与全量分析、监控选目标、SSH 任务。
- **分析状态 / 读取文件 / 运行白名单命令 / …**：细粒度能力（见页面说明）。
- **自动修复最高风险**：仅影响「修改配置文件」类能力；默认 `none` 禁止自动改文件。

### 4.3 全局（所有已授权服务器共用）

- **允许改动的路径**（glob）
- **允许的命令前缀**（每行一个）

### 4.4 硬安全边界（不可关闭）

`sudo`、`su`、`systemctl`、`chmod/chown`、`visudo` 等提权或系统级变更命令**一律拒绝**，无法通过策略放开。

## 5. 分析（规则引擎）

### 5.1 报告从哪来

- 页面 **「立即分析全部服务器」**：本机 + 所有已登记 SSH，**每台一条报告**；同一批共享 `batchId`。
- **自动化** 定时任务（见第 7 节）：默认每天 08:00 全量分析。
- 未授权或连接失败也会写入 **失败报告**（`status: error`），便于排查。

### 5.2 规则做什么

采集负载、内存、`df`、journal/syslog 等，按阈值与关键词生成：

- 发现（findings）、严重级别、摘要、可能原因、建议步骤（**不自动执行**）。

**不使用 LLM**；报告内容 deterministic。

### 5.3 列表与删除

- 列表点行进入 `/analysis?id=...` 详情。
- 可勾选多条 **删除所选**；详情页可 **删除本报告**。

### 5.4 API（可选）

- `GET /api/server/analyze` — 列表  
- `POST /api/server/analyze` — body：`{ "scope": "fleet" | "local" | "host", "hostId?" }`  
- `DELETE /api/server/analyze` — body：`{ "ids": ["sar_...", ...] }`  
- `GET /api/server/analyze/[id]` — 单条

## 6. 监控（对话）

### 6.1 使用方式

1. 顶部（或页内）选择 **本机** 或 **SSH 主机**（远程须已授权）。
2. 用自然语言提问，例如：磁盘空间、内存负载、tail 日志、读 nginx 配置等。

### 6.2 LLM 与规则

| 条件 | 行为 |
|------|------|
| 已配置 `OPENROUTER_API_KEY`（或 AI Gateway 等，见环境变量） | **LLM** 理解意图，通过工具调用执行只读命令 |
| 未配置 Key | **本地规则引擎**（关键词匹配：磁盘、日志、journal、概览等） |
| LLM 调用失败 | 自动 **回退** 到规则引擎 |

页头会显示当前模式：`LLM 编排监控` 或 `本地规则引擎`。

**分析报告、Cron、权限校验** 均不经过 LLM。

### 6.3 API

- `POST /api/monitor/chat` — body：`{ "messages": [...], "targetHostId": null | "主机id" }`  
- `GET /api/monitor/chat` — 查看是否启用 LLM、模型 id

## 7. 自动化（Cron）

### 7.1 调度器

- 应用启动时注册任务（`src/instrumentation.ts`）。
- 首次若无全量分析任务，自动创建：**每日 08:00 全量服务器分析报告**（`0 8 * * *`，`Asia/Shanghai`）。
- `DISABLE_TASK_SCHEDULER=1` 关闭调度（仍可在 UI **立即运行**）。

### 7.2 新建任务表单

| 字段 | 说明 |
|------|------|
| **任务名称** | 短标题，列表展示 |
| **任务描述** | 备注，给人看，不参与执行逻辑 |
| **Cron / 时区** | 五段式 cron + IANA 时区 |
| **目标主机** | 全部 / 本机 / 某台 SSH |
| **命令（可选）** | **留空** → 对所选范围 **生成分析报告**；**填写** → 在所选主机执行白名单命令 |

注意：**执行命令** 时不能选「全部服务器」，需选本机或单台 SSH。

### 7.3 任务类型（内部映射，供排查）

| 用户意图 | 内部 kind |
|----------|-----------|
| 分析报告 + 全部 | `analyze_fleet` |
| 分析报告 + 本机 | `analyze_local` |
| 分析报告 + 单台 SSH | `analyze_host` |
| 命令 + 本机 | `command_local` |
| 命令 + SSH | `command_ssh` |

### 7.4 操作

- **立即运行** / **启用·停用** / **删除**
- **最近执行记录** 显示每次触发结果摘要

## 8. 环境变量

在项目根创建 **`.env.local`**（勿提交 git）。常用项：

```bash
# —— 监控 LLM（可选）——
OPENROUTER_API_KEY=sk-or-v1-...
MONITOR_AI_MODEL=deepseek/deepseek-chat
# OPENROUTER_MODEL=...          # 与 MONITOR_AI_MODEL 二选一优先 MONITOR_AI_MODEL
# OPENROUTER_HTTP_REFERER=http://localhost:3000
# OPENROUTER_APP_TITLE=Infini Ops Agent   # 须 ASCII

# 或使用 AI Gateway / OpenAI 兼容（见 src/lib/llm-model.ts）
# AI_GATEWAY_API_KEY=...
# OPENAI_API_KEY=...

# —— SSH ——
# SERVER_SSH_CONFIG=/path/to/ssh/config
# SSH_HOSTS_PATH=/path/to/ssh-hosts.json

# —— 数据文件路径（可选，默认均在 data/）——
# SERVER_AGENT_POLICY_PATH=...
# SERVER_ANALYSIS_STORE_PATH=...
# SCHEDULED_TASKS_PATH=...
# TASK_RUNS_PATH=...

# —— 调度 ——
# DISABLE_TASK_SCHEDULER=1
```

## 10. 典型工作流

### 10.1 每日自动巡检

1. **主机**：登记所有 SSH。  
2. **权限**：每台开启「授权 Agent 访问」+「分析状态」。  
3. **自动化**：确认存在 08:00 全量任务（或自建：目标 **全部**，命令 **留空**）。  
4. **分析**：次日查看列表；失败项看 `errorMessage`（未授权、密钥、网络等）。

### 10.2 临时排查一台机器

1. **权限**：确认该主机已授权。  
2. **监控**：目标选该主机，提问或让 LLM 拉日志/磁盘。  
3. 或 **分析** 页立即全量 / 仅对该机 POST `scope: "host"`。

### 10.3 定时只读命令

1. **权限**：该主机开启「运行白名单命令」，命令前缀在全局列表中。  
2. **自动化**：选本机或 SSH，填写命令（如 `df -h`），本机可选「无人值守」。

## 11. 故障排查

| 现象 | 可能原因 |
|------|----------|
| 权限页只有本机 | 未在 **主机** 登记 SSH |
| 远程分析/监控拒绝 | 该主机 **未授权** 或能力未开 |
| SSH 测试失败 | 私钥路径错误、网络、用户名、Port、`StrictHostKeyChecking` |
| 命令被拒绝 | 不在 **allowedCommands** 前缀列表，或含禁止元字符 |
| Cron 不跑 | 服务未常驻、任务被停用、`DISABLE_TASK_SCHEDULER=1`、cron 表达式无效 |
| 监控只会关键词回复 | 未配置 `OPENROUTER_API_KEY` |
| 全量分析部分失败 | 正常；失败台会单独成报告，查权限与 SSH |

## 12. 架构速览

```
浏览器 → Next.js App Router
           ├─ 监控：LLM（可选）+ 工具 / 规则回退
           ├─ 分析：规则引擎 + 本机采集 / SSH 只读命令
           ├─ 权限：JSON 策略 + agent-policy 校验
           └─ 自动化：node-cron → executor → 分析 / 命令
```
